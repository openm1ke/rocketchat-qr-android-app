# Пропуск в кампус

Flutter-клиент для Android и iOS. Исходный Android-клиент находится в корне репозитория.

## Запуск

Из каталога Flutter-клиента:

```sh
flutter pub get
flutter analyze
flutter test
flutter run
```

Команда для создания APK:

```sh
flutter build apk --debug
```

Для iOS понадобится macOS с Xcode.

Вставьте токен личного доступа Rocket.Chat в приложении и нажмите «Сохранить и получить QR». Токен хранится в защищённом хранилище приложения.

Клиент открывает диалог с `qr-code-generator.bot`, подписывается на сообщения и отправляет `/enter`. Полученный PNG хранится в памяти до истечения срока. Если бот сообщает дату окончания, приложение показывает её под QR и скрывает код с начала указанного дня по местному времени устройства. Для ответов без даты действует прежнее локальное правило — 30 секунд с момента получения. Приложение запрашивает код при запуске с сохранённым токеном. Кнопка на экране позволяет запросить новый код при истечении срока или отказе турникета.

Тесты используют локальный WebSocket-сервер и фиктивный токен. Для проверки кампусного бота нужен действующий токен.

## Ручная сборка релизного APK

В GitHub откройте **Actions → Android release APK → Run workflow** и выберите основную ветку `master`. После успешной сборки подписанный APK появится в разделе **Releases** как файл релиза. Копия также доступна в **Artifacts** соответствующего запуска. Номер сборки берётся из номера запуска workflow.

Для подписи добавьте в **Settings → Secrets and variables → Actions** следующие секреты:

- `ANDROID_KEYSTORE_BASE64` — содержимое релизного keystore в Base64.
- `ANDROID_KEYSTORE_PASSWORD` — пароль keystore.
- `ANDROID_KEY_ALIAS` — псевдоним ключа.
- `ANDROID_KEY_PASSWORD` — пароль ключа.

Используйте один и тот же ключ для релизов, которые должны устанавливаться как обновления. Для локальной подписанной сборки задайте путь к keystore в `ANDROID_KEYSTORE_PATH` и те же переменные с паролями и псевдонимом, затем выполните `flutter build apk --release`.
