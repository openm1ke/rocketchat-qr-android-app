# Пропуск в кампус

Flutter-клиент для Android и iOS. Исходный Android-клиент находится в корне репозитория.

## Запуск

Из каталога Flutter-клиента:

```sh
flutter pub get
flutter analyze
flutter test
flutter run
```

Команда для создания APK:

```sh
flutter build apk --debug
```

Для iOS понадобится macOS с Xcode.

На экране подключения введите логин и пароль Rocket.Chat Школы 21. Приложение входит во временную сессию, создаёт отдельный персональный токен для устройства и сохраняет только его в защищённом хранилище. Затем временная сессия закрывается. Пароль не сохраняется. Если сервер запрашивает подтверждение, введите код из аутентификатора или письма; для подтверждения паролем используется SHA-256. Для использования создаваемого токена выбран режим «Игнорировать двухфакторную аутентификацию» (`bypassTwoFactor: true`). Подтверждение самого входа и создания токена выполняется по требованиям сервера.

Если сервер запрещает вход паролем или создание персональных токенов, выберите «У меня есть токен», вставьте готовый токен и нажмите «Сохранить и получить QR». Уже сохранённые токены продолжают работать. Персональный токен не истекает по времени, но может быть отозван или удалён администратором — в этом случае приложение предложит подключиться заново.

Ссылка «Где взять токен?» на экране подключения и в настройках открывает инструкцию из трёх шагов со скриншотами настольного Rocket.Chat. Нажмите на изображение, чтобы открыть его целиком и увеличить жестом.

Клиент открывает диалог с `qr-code-generator.bot`, подписывается на сообщения и отправляет `/enter`. Полученный PNG хранится в памяти до истечения срока. Если бот сообщает дату окончания, приложение показывает её под QR и скрывает код с начала указанного дня по местному времени устройства. Для ответов без даты действует прежнее локальное правило — 30 секунд с момента получения. Приложение запрашивает код при запуске с сохранённым токеном. Кнопка на экране позволяет запросить новый код при истечении срока или отказе турникета.

Тесты используют локальный WebSocket-сервер и фиктивный токен. Для проверки кампусного бота нужен действующий токен.

Сценарии входа и создания персонального токена проверяются на локальном HTTP-сервере: права, 2FA, отсутствие токена в ответе, запрет перенаправлений и закрытие временной сессии. Тесты интерфейса проверяют подтверждение входа, сбой сохранения и работу на узком экране с увеличенным текстом. Настройки предыдущего оформления переходят на светлый нейтральный стиль; размер QR, яркость и другие параметры сканирования сохраняются.

## Ручная сборка релизного APK

В GitHub откройте **Actions → Android release APK → Run workflow** и выберите основную ветку `master`. После успешной сборки подписанный APK появится в разделе **Releases** как файл релиза. Копия также доступна в **Artifacts** соответствующего запуска. Номер сборки берётся из номера запуска workflow.

Для подписи добавьте в **Settings → Secrets and variables → Actions** следующие секреты:

- `ANDROID_KEYSTORE_BASE64` — содержимое релизного keystore в Base64.
- `ANDROID_KEYSTORE_PASSWORD` — пароль keystore.
- `ANDROID_KEY_ALIAS` — псевдоним ключа.
- `ANDROID_KEY_PASSWORD` — пароль ключа.

Используйте один и тот же ключ для релизов, которые должны устанавливаться как обновления. Для локальной подписанной сборки задайте путь к keystore в `ANDROID_KEYSTORE_PATH` и те же переменные с паролями и псевдонимом, затем выполните `flutter build apk --release`.

## Экран пропуска и журнал

На главном экране остаются QR, кнопки информации, настроек и обновления. Срок действия и подсказка скрываются через три секунды после получения QR; посмотреть срок повторно можно по кнопке информации. Ошибки остаются видимыми. Для QR сохраняется белая подложка с полями.

Живой фон использует от двух до пяти рисуемых цветовых полей, обновляется не чаще 24 раз в секунду и останавливается при уходе приложения в фон или перекрытии экрана другим маршрутом. Системное уменьшение анимации делает фон статичным. Ползунок движения в нуле делает свечение статичным; режим «Сплошной цвет» полностью отключает свечение.

**Настройки → Для разработчиков → Журнал запросов** показывает последние 200 событий в памяти: HTTP, методы и кадры WebSocket, результаты и длительности. Есть фильтры, очистка и копирование отдельной записи. Счётчики показывают HTTP-попытки, исходящие методы WS и события с ошибками; ответы WS не считаются повторным запросом. Журнал очищается при перезапуске приложения.

Логины, пароли и их хеши, коды 2FA, токены, заголовки авторизации, cookies и персональные идентификаторы маскируются до сохранения записи. Тексты сообщений, QR и бинарные данные не записываются. Для изображений сохраняются тип и размер. Скопированные записи содержат те же маскированные данные. Трассировку действий, выполненных до добавления журнала, восстановить нельзя.

## Простые настройки оформления

В **Настройки → Оформление** сначала выберите режим. Предпросмотр сразу показывает результат, изменения сохраняются автоматически.

- **Свечение**: интенсивность движения от 0 до 100% и от двух до пяти основных цветов. В нуле градиент статичен; выше увеличиваются скорость и размах движения. Нажмите на кружок, чтобы открыть визуальный колор-пикер, или «+», чтобы добавить цвет. В пикере можно удалить цвет, если их больше двух. Есть готовые палитры «Мягкая» и «Матрица».
- **Сплошной цвет**: только заливка, без свечения и его настроек.

**Цвет фона** задаёт заливку или основу под свечением. **Цвет акцента** меняет кнопки и элементы управления. Изменение цвета не переключает режим; переключение режима сохраняет основу, палитру и движение. **Тема меню** задаёт светлый, тёмный или системный вид настроек и элементов управления.

«Матрица» включает чёрную основу и палитру из светло-зелёного, тёмно-зелёного и чёрного. Собственные цвета, акцент и движение сохраняются между запусками. Старые настройки с выключенным движением переходят на интенсивность 0; старые варианты фона приводятся к двум новым режимам.
